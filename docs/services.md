## Known Repo/Server Drift (found during 2026-09-18 live audit)

- The `/mnt/homelab_projects/homelab-ops` checkout **on the server itself** is a separate git clone from this repo, and had untracked local copies of `arr-stack.yml`/`webtop.yml` blocking a plain `git pull` there. Not fixed as part of this audit — worth reconciling so `git pull` on the server works cleanly again.
- Several `docker compose` invocations on the server appear to have been run without an explicit `-p <project>` flag from inside the shared `configs/docker-compose/` directory, so Compose defaults all of them to the *same* project name (the folder name). This makes `--remove-orphans` dangerous — it can (and on 2026-09-18, did) remove *other* unrelated running services. **Always pass an explicit `-p <service-name>` or `-f <file>.yml` without `--remove-orphans` when deploying a single service from this directory.**
- Extra untracked compose files exist on the server that aren't part of any documented service and aren't in this repo either: `homelable.yml`, `netdata.yml`, `uptime-kuma.yml`, `t3code-2.yml`, `t3code-3.yml` — worth checking what these are and whether they should be tracked, deployed, or deleted.
