## 2026-09-21 (66)
- **Freed 14GB inside `yado-hosts` (LXC 101), then discovered + fixed the much bigger real problem: `local-lvm` thin pool was 88.80% full partly because thin-provisioned space never gets reclaimed on file deletion without an explicit TRIM.** Started by cleaning up `yado-hosts` — flagged during (62)'s LXC audit as the tightest LXC at 85.7%/30GB. `df` showed 24GB used but `du` on visible directories only accounted for ~4GB; `docker system df` found the real culprit: **17.97GB of Docker build cache** (11.79GB reclaimable) plus 6 unused images (14 total, 8 active). `docker builder prune -f` + `docker image prune -a -f` reclaimed ~14GB inside the guest (24GB→10GB used, 4.6GB→18GB free) — **but `lvs -a pve` still showed the underlying thin volume at 85.68% used**, unchanged. Ran `pct fstrim` on **all 4 LXCs** (100/101/102/103) as a matter of course — every one had substantial reclaimable space, most dramatically `docker-host` (LXC 100): 89.7GiB trimmed, volume usage 61.92%→40.32%. **Overall `local-lvm` thin pool usage: 88.80%→55.24%, real free headroom: ~18GB→~70GB.** This directly changes the calculus from (62)'s "the 4-LXC media/personal/drive/infra split doesn't fit" conclusion — there's now comfortably enough room to revisit that plan at full scope if the user still wants it, instead of the reduced-scope `personal-hosts` merge from (64). **Should become a routine maintenance step** (a periodic `pct fstrim` across all LXCs, or automating it) rather than a one-off — thin-pool bloat from undiscarded deleted blocks will silently recur.
